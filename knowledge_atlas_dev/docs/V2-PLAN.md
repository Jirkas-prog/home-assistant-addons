## Decisions made in this checkpoint

- Use concrete, consistent feature names for navigation and headings throughout the interface. Keep supporting descriptions short and factual; do not use promotional slogans as titles.
- Keep ordinary Markdown as the source of truth; no mandatory database or AI service.
- Use field-level three-way comparisons. Do not guess through overlapping body edits.
- Restore a full library transactionally instead of silently merging IDs and paths. Preserve the old directory and leave external roots untouched.
- Store unpublished drafts locally and label them clearly; they are not included in server backups or published search/statistics until saved.
- Keep schema 1 readable; migrate explicitly or on a user's record save. Do not rewrite the running personal library during development.
- Keep V2 on its development branch until its acceptance gates are met. The earlier publication of 1.2.0 does not make this development checkpoint a completed V2 release.

## Next implementation order

Extend recovery guidance and remaining settings/mobile acceptance, then implement MZ-12/14/18/20 with statistics definitions. Build project management on those models, then document study/search/import, map scaling and optional integrations. MZ-06 can proceed independently when an HA test instance is available.
